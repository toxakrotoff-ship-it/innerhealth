# ПВЗ Ozon через CDN

Используется существующий `NEXT_PUBLIC_CDN_URL`. Секреты Delivery API и данные покупателей в публикацию не попадают: JSON содержит только публичные ID, названия и адреса ПВЗ (и координаты, если они есть в кэше).

После полной синхронизации каждой витрины создаются JSON населённых пунктов в `public/uploads/ozon-pvz/<brand>/cities/<sha256-содержимого>/<sha256-города>.json`. Затем атомарно заменяется manifest этой витрины. Публикация переживает пересоздание app благодаря существующему uploads volume. Неполный кэш или ошибка записи не переключают manifest. Предыдущие файлы сохраняются для уже открытых клиентов; учитывать каталог публикаций при контроле диска.

Чекаут при каждом поиске читает `/api/ozon-pvz/manifest?city=...&brand=...` с домена сайта и `Cache-Control: no-store`. Ответ содержит только указатель выбранного города. По нему браузер получает JSON через CDN: `/api/ozon-pvz/cities/<brand>/<sha256-содержимого>/<sha256-города>.json`. Изменение данных меняет URL, поэтому ночное обновление доступно при следующем поиске без ожидания TTL или очистки CDN. Улица фильтруется в загруженном справочнике; интерфейс показывает до 30 результатов. В браузер загружается выбранный населённый пункт, а не полный справочник страны.

Снимки имеют `Cache-Control: public, max-age=31536000, immutable`, `ETag` и `Access-Control-Allow-Origin: *`. Ошибки имеют `no-store`. CDN должен учитывать эти заголовки и разрешать кэширование `/api/ozon-pvz/cities/*`, если существует общее исключение для `/api/*`. CSP сайта должен разрешать `connect-src` к настроенному CDN.

При отсутствии CDN, публикации или записи города, устаревшем кэше, таймауте, повреждённом JSON или несовпадении SHA-256 используется текущий `/api/ozon-delivery/points`. Неоднозначные и неразобранные названия населённых пунктов также остаются на текущем поиске API. Снимок старше 48 часов не используется. Отмена поиска не запускает лишний fallback. Расчёт цены, проверка доступности и оформление отправлений выполняются сервером независимо от источника справочника.

## Выкладка и проверка

1. Пересобрать app с `NEXT_PUBLIC_CDN_URL`; новые API-маршруты и CSP входят в сборку. Для координат применить соответствующую миграцию, если включается карта.
2. Выполнить существующий `sudo PROJECT_DIR=/opt/innerhealth/nextjs-project /opt/innerhealth/ops/ozon-points-sync.sh`. Ежедневное задание в 04:15 также публикует JSON после загрузки обеих витрин. До первой публикации работает fallback API.
3. Проверить свежий manifest города с origin: `no-store`, корректная витрина, дата и путь снимка.
4. Загрузить путь снимка с CDN: HTTP 200, CORS `*`, immutable, SHA-256 соответствует версии в URL. Повторный запрос проверить по диагностическим заголовкам CDN на HIT.
5. После изменения справочника проверить смену URL, а при блокировке CDN — работу поиска через API. Новые версии видны при следующем поиске; уже выбранный пункт самопроизвольно не меняется.
