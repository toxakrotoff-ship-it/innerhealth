# Product Documents PR-6

## Что добавлено

- Структурированная модель `ProductDocument` + many-to-many `ProductDocumentProduct`.
- Типы документов: `CERTIFICATE`, `DECLARATION`, `TEST_REPORT`, `INSTRUCTION`, `LABEL`, `OTHER`.
- Brand-scoped CRUD документов внутри редактора товара.
- Загрузка файлов в существующую инфраструктуру `public/uploads/*`, новая подпапка: `public/uploads/documents`.
- Публичный SSR-блок `Документы` на карточке товара.
- Legacy fallback: если structured documents отсутствуют, старый `documents` tab продолжает работать.

## Модель данных

- `ProductDocument`
  - хранит метаданные документа и ссылку на файл;
  - принадлежит одному brand scope;
  - может быть опубликован/скрыт через `isPublished`.
- `ProductDocumentProduct`
  - связывает один документ с несколькими товарами;
  - хранит порядок документа внутри конкретного товара.

## Типы документов

| Type | Название | Назначение |
| --- | --- | --- |
| `CERTIFICATE` | Сертификат | Сертификаты соответствия и качества |
| `DECLARATION` | Декларация соответствия | Декларации ТР ТС / ЕАЭС |
| `TEST_REPORT` | Протокол испытаний | Лабораторные протоколы |
| `INSTRUCTION` | Инструкция | Инструкции по применению |
| `LABEL` | Маркировка | Этикетки и маркировочные материалы |
| `OTHER` | Другой документ | Прочие файлы |

## Storage и ограничения

- Используется существующая файловая система в `public/uploads`.
- Документы сохраняются в `public/uploads/documents`.
- В БД хранится только URL и метаданные файла, без base64.
- Максимальный размер файла: `20 MB`.
- Разрешённые MIME:
  - `application/pdf`
  - `image/jpeg`
  - `image/png`
  - `image/webp`
- MIME определяется на сервере по сигнатуре файла, а не только по `Content-Type` клиента.

## Brand scope

- Brand берётся только из trusted admin context.
- Документ нельзя привязать к товару другого бренда.
- Поиск существующих документов фильтруется по активному бренду.
- Публичная выдача документов фильтруется по brand scope товара.

## Админский workflow

### Как загрузить документ

1. Откройте товар в админке.
2. Перейдите в секцию `Документы товара`.
3. В блоке `Создать новый документ` загрузите файл.
4. Выберите тип, задайте название и при необходимости номер/даты.
5. Нажмите `Создать и привязать`.

### Как привязать документ к нескольким товарам

1. Откройте второй товар.
2. В блоке `Привязать существующий` найдите документ по названию, номеру или имени файла.
3. Нажмите `Привязать`.

### Как заменить файл

1. Найдите нужный документ в списке привязанных.
2. В поле `Заменить файл` загрузите новый PDF/изображение.
3. Нажмите `Сохранить`.

### Как скрыть документ

1. Снимите флаг `Опубликован`.
2. Нажмите `Сохранить`.

### Как отвязать документ

1. Нажмите `Отвязать`.
2. Документ исчезнет только у текущего товара и останется у других связанных товаров.

### Как удалить документ

1. Нажмите `Удалить`.
2. Документ удалится полностью вместе со всеми связями.

## Публичное поведение

- Если у товара есть structured documents, показывается новый блок `Документы`.
- Старый rich-text tab `Документы` скрывается, чтобы не было дубля.
- Если structured documents нет, legacy tab остаётся fallback-вариантом.
- На витрине показываются только опубликованные документы.

## Revalidation

- После create/update/attach/detach/delete/reorder ревалидируются только затронутые product pages.
- Полное ревалидирование сайта не используется.

## Known limitations

- Отдельный общий экран `/admin/product-documents` пока не добавлен.
- Файлы лежат в публичном storage, поэтому `isPublished` управляет только витринной выдачей данных, а не доступностью прямого URL.
- Старые rich-text ссылки из legacy tabs не мигрируются автоматически.
